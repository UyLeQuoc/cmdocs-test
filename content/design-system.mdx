# Design System

This page showcases **every component** available in cmdocs. All components come from [Fumadocs UI](https://fumadocs.dev/docs/ui/components) — they are automatically imported, so you never need to write import statements in your MDX files.

---

## Callout

Callouts highlight important information. There are three types: `info`, `warn`, and `error`.

### Info Callout

<Callout type="info">
  This is an informational callout. Use it for helpful tips, notes, and background context. Supports **markdown** and `inline code`.
</Callout>

```mdx
<Callout type="info">
  This is an informational callout.
</Callout>
```

### Warning Callout

<Callout type="warn">
  This is a warning callout. Use it to alert users about potential issues, breaking changes, or caveats.
</Callout>

```mdx
<Callout type="warn">
  This is a warning callout.
</Callout>
```

### Error Callout

<Callout type="error">
  This is an error/danger callout. Use it for critical warnings, destructive actions, or security notices.
</Callout>

```mdx
<Callout type="error">
  This is an error/danger callout.
</Callout>
```

### Default Callout (no type)

<Callout>
  A default callout without a type specified. This renders with the default styling.
</Callout>

```mdx
<Callout>
  A default callout without a type.
</Callout>
```

## Tabs

Tabs let you organize content into switchable panels. Use the `items` prop to define tab labels, and `<Tab>` with a matching `value` for each panel.

### Basic Tabs

<Tabs items={["React", "Vue", "Svelte"]}>
  <Tab value="React">
    React uses JSX and a virtual DOM for building user interfaces.

    ```jsx
    function App() {
      return <h1>Hello React!</h1>
    }
    ```
  </Tab>
  <Tab value="Vue">
    Vue uses a template syntax with reactive data binding.

    ```vue
    <template>
      <h1>Hello Vue!</h1>
    </template>
    ```
  </Tab>
  <Tab value="Svelte">
    Svelte compiles your code at build time for maximum performance.

    ```svelte
    <h1>Hello Svelte!</h1>
    ```
  </Tab>
</Tabs>

```mdx
<Tabs items={["React", "Vue", "Svelte"]}>
  <Tab value="React">React content here...</Tab>
  <Tab value="Vue">Vue content here...</Tab>
  <Tab value="Svelte">Svelte content here...</Tab>
</Tabs>
```

## Steps

Steps provide numbered, sequential instructions. Each `<Step>` is a numbered item within the `<Steps>` container.

<Steps>
  <Step>
    ### Create your project

    Start by creating a new directory for your documentation project and initializing it.

    ```bash
    mkdir my-docs && cd my-docs
    ```
  </Step>
  <Step>
    ### Add your content

    Create a `docs.json` configuration file and add your first MDX page.

    ```json
    {
      "name": "My Project",
      "navigation": {
        "tabs": [{
          "tab": "Docs",
          "groups": [{
            "group": "Getting Started",
            "pages": ["index"]
          }]
        }]
      }
    }
    ```
  </Step>
  <Step>
    ### Deploy

    Connect your GitHub repository to cmdocs and deploy automatically on every push.

    <Callout type="info">
      Deployments are triggered automatically when you push to the configured branch.
    </Callout>
  </Step>
</Steps>

```mdx
<Steps>
  <Step>
    ### Create your project
    Start by creating a new directory...
  </Step>
  <Step>
    ### Add your content
    Create a `docs.json` configuration file...
  </Step>
  <Step>
    ### Deploy
    Connect your GitHub repository...
  </Step>
</Steps>
```

## Accordion

Accordions are collapsible sections powered by Radix UI. Wrap individual `<Accordion>` items in `<Accordions>`.

<Accordions>
  <Accordion title="What is cmdocs?">
    cmdocs is a self-hosted documentation platform powered by Fumadocs and Next.js. It reads Mintlify-format `docs.json` and MDX files and renders beautiful documentation sites.
  </Accordion>
  <Accordion title="What rendering engine does cmdocs use?">
    cmdocs uses **Fumadocs v16** with **Next.js 16** and **Tailwind CSS v4**. The output is a statically exported Next.js site (no server runtime needed).
  </Accordion>
  <Accordion title="Is it free?">
    Yes! cmdocs is open-source and free to self-host. Deploy your documentation anywhere — S3, Vercel, Netlify, nginx, or use the cmdocs platform dashboard for managed hosting.
  </Accordion>
  <Accordion title="Does it support dark mode?">
    Yes, dark mode is built-in via `next-themes`. It works automatically with all Fumadocs components and respects the user's system preference.
  </Accordion>
</Accordions>

```mdx
<Accordions>
  <Accordion title="What is cmdocs?">
    cmdocs is a self-hosted documentation platform...
  </Accordion>
  <Accordion title="Is it free?">
    Yes! cmdocs is open-source and free to use.
  </Accordion>
</Accordions>
```

## Code Blocks

Code blocks are powered by [Shiki](https://shiki.style/) for syntax highlighting. Fumadocs supports title annotations, line highlighting, and word highlighting out of the box.

### Basic Code Block

```typescript
interface DocsConfig {
  name: string;
  description?: string;
  theme: {
    colors: { primary: string };
    darkMode: boolean;
  };
  navigation: {
    tabs: NavigationTab[];
  };
}
```

### Code Block with Title

```typescript title="lib/source.ts"
import { docs, meta } from "@/.source";
import { createMDXSource } from "fumadocs-mdx";
import { loader } from "fumadocs-core/source";

export const source = loader({
  baseUrl: "/",
  source: createMDXSource(docs, meta),
});
```

### Multi-Language Code Blocks

Use Tabs to show the same concept in multiple languages:

<Tabs items={["TypeScript", "Rust", "Python"]}>
  <Tab value="TypeScript">
    ```typescript title="handler.ts"
    async function handleRequest(req: Request): Promise<Response> {
      const { slug } = req.params;
      const page = source.getPage(slug.split("/"));

      if (!page) {
        return new Response("Not found", { status: 404 });
      }

      return Response.json(page.data);
    }
    ```
  </Tab>
  <Tab value="Rust">
    ```rust title="handler.rs"
    async fn handle_request(
        Path(slug): Path<String>,
    ) -> impl IntoResponse {
        match source.get_page(&slug) {
            Some(page) => Json(page.data).into_response(),
            None => StatusCode::NOT_FOUND.into_response(),
        }
    }
    ```
  </Tab>
  <Tab value="Python">
    ```python title="handler.py"
    async def handle_request(slug: str):
        page = source.get_page(slug.split("/"))

        if not page:
            raise HTTPException(status_code=404)

        return page.data
    ```
  </Tab>
</Tabs>

## Banner

Banners display site-wide announcements at the top of every page.

<Callout type="info">
  Banners are typically placed in your root layout, not in individual MDX pages. The example below shows the syntax:
</Callout>

```tsx title="app/layout.tsx"
import { Banner } from "fumadocs-ui/components/banner";

export default function Layout({ children }) {
  return (
    <html>
      <body>
        <Banner>
          🎉 cmdocs v2.0 is now available! Powered by Fumadocs v16.
        </Banner>
        {children}
      </body>
    </html>
  );
}
```

## Combining Components

The real power comes from combining components together. Here's a real-world example:

### Getting Started Guide

<Steps>
  <Step>
    ### Choose your setup method

    <Tabs items={["Platform (Recommended)", "CLI", "Manual"]}>
      <Tab value="Platform (Recommended)">
        Sign up at [cmdocs.dev](https://cmdocs.dev) and connect your GitHub repository. Your docs will be automatically built and deployed on every push.
      </Tab>
      <Tab value="CLI">
        Install the CLI globally:

        ```bash
        npm install -g @cmdocs/cli
        ```

        Then run:

        ```bash
        cmdocs dev --source ./docs
        ```
      </Tab>
      <Tab value="Manual">
        Clone the template and customize it manually:

        ```bash
        git clone https://github.com/commandoss/cmdocs-template
        cd cmdocs-template
        bun install && bun dev
        ```
      </Tab>
    </Tabs>
  </Step>
  <Step>
    ### Configure your project

    Create or update your `docs.json`:

    <TypeTable
      type={{
        name: { type: "string", description: "Your project name", required: true },
        navigation: { type: "object", description: "Sidebar navigation config", required: true },
        theme: { type: "object", description: "Colors and theming options" },
      }}
    />

    <Callout type="warn">
      The `navigation` field is required. Without it, your site will have no sidebar.
    </Callout>
  </Step>
  <Step>
    ### Add your content

    Your project structure should look like this:

    <Files>
      <Folder name="docs" defaultOpen>
        <File name="docs.json" />
        <File name="index.mdx" />
        <File name="quickstart.mdx" />
        <Folder name="guides">
          <File name="setup.mdx" />
        </Folder>
      </Folder>
    </Files>
  </Step>
</Steps>

### FAQ Section

<Accordions>
  <Accordion title="Can I migrate from Mintlify?">
    Yes! cmdocs is designed to be a drop-in replacement for Mintlify. Just point it at your existing `docs.json` and MDX files — no content changes needed.

    <Callout type="info">
      Components like `<Note>`, `<Tip>`, and `<Warning>` are automatically converted to Fumadocs `<Callout>` variants.
    </Callout>
  </Accordion>
  <Accordion title="What about search?">
    cmdocs uses [Orama](https://orama.com/) for client-side full-text search. It's free, self-hosted, and works with static exports. Press `⌘K` (or `Ctrl+K`) to try it.
  </Accordion>
  <Accordion title="Can I use custom components?">
    You can add any React component to your MDX files. However, we recommend using Fumadocs' built-in components whenever possible — they handle dark mode, responsive design, and accessibility automatically.
  </Accordion>
</Accordions>
